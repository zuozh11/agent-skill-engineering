# SRM 接口规划约定迁移材料

以下条款来自原 `to-api` 的 SRM 项目约定，供采用相应平台的项目迁入自身 RULE。它们不随通用 Skill 自动生效；迁入时依据目标项目已确认的约定选择条款，并写清适用模块与必要例外。

- 已采用生成式 Controller 的模块，新路由沿用现有前缀及 `POST /{module}/{method}` 风格。
- 项目明确要求替换生成式 Save 时：写入语义与原 Save 不一致则新增业务命令或内部入口，并将原公开 Save 列入停用。
- 同一业务路由由多个入口调用时，使用已确认的请求字段区分；仅入口不同不复制同类接口。
- 本期无需改造的平台能力继续复用：登录鉴权、BPM 待办与提交/退回/驳回、公共附件上传下载、相邻主数据详情。
- 已确认页面内切换、勾选或批量填写使用首次详情返回的对象图时，不另增查询或保存接口，并说明相关 ID 的流转。
- 已确认属于聚合内部结构的子资源保留在聚合对象图中，不按数据表机械拆分路由。

不同的 HTTP 风格、Save 保留要求或资源访问边界，以目标项目当前需求和适用 RULE 为准。迁入项目时，每个 RULE 保持一个约束及其适用条件。
