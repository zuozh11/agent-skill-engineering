# 隔离执行

仅当 `impl` 已选用隔离 worktree、使用 `-w` 或 `-a` 时完整读取并使用本文件。按实际选中的分支执行对应章节。

## `-a` 编排

为每个实现单元创建或 fork 独立子 Agent，或者创建可隔离各实现单元的 workflow。编排入口负责提供任务目标、已确认方案、相关项目规则、工作目录、依赖状态和验收标准，并负责调度、隔离、集成和最终审计；子 Agent 或 workflow 节点负责实现、验证和提交。多个可并行实现单元可以并行调度；共享写集、明显冲突或依赖尚未集成时串行调度。宿主既无法创建子 Agent，也无法创建 workflow 时暂停并说明，不得自动降级为当前 Agent 直接实现。

`-a -w` 同时强制子 Agent 或 workflow 编排和隔离 worktree。

## worktree

选用隔离 worktree 或 `-w` 时执行。

每个独立交付的实现单元使用独立 worktree、Git 索引和临时分支；依赖任务集成后，后续任务才从最新目标分支创建 worktree。共享写集或明显冲突的任务串行处理。无法安全创建 worktree 时暂停并说明原因。

每个 worktree 只处理对应实现单元，并记录 `atomic-commit` 交付的 SHA。

## 集成

隔离 worktree 在提交后按本节集成。按任务卡编号或实现单元顺序，cherry-pick 每个实现单元的 commit：

- 冲突时中止本次集成并保留 worktree；在对应 worktree 中基于最新目标分支处理。冲突来自主工作区相关未提交改动时暂停。
- 单个任务失败不影响无依赖任务，只阻塞依赖它的后续任务。
- 集成成功后移除 worktree 和临时分支；失败时保留并报告路径、分支和原因。
