# 最小实现阶梯

先读懂需求、消费者和真实调用路径，再停在第一项成立的位置：

1. **delete**：改动或现有结构没有真实消费者，或只服务未确认的未来需求；删除且不替代。
2. **reuse**：代码库已有 helper、类型、模块或惯用法可以完成；复用真实所有者。
3. **stdlib**：标准库已经提供；指出具体能力。
4. **native**：浏览器、数据库、运行时或框架已经提供；指出具体机制。
5. **dependency**：已安装依赖已经提供，或新增依赖只替代少量朴素代码；不增加依赖。
6. **shrink**：以上都不成立时，使用文件和概念更少的最小正确实现。

两个方案都可行时选择更高一项。同一层级选择文件更少、概念更少且边界行为正确的朴素方案。删除优于新增，替换优于叠加。
