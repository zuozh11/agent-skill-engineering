# Resolving Merge Conflicts

1. **确认当前状态。** 检查 Git 状态、历史记录和冲突文件，区分正在进行的是 merge 还是 rebase，并读取适用的项目规则。

2. **查明双方意图。** 为每处冲突找到一手依据，理解两边改动的原因和原始意图。优先读取相关提交消息、代码历史、PR、Issue、任务卡和需求文档。

3. **逐块解决冲突。** 能兼容时保留双方意图；无法兼容时，选择符合本次 merge/rebase 明确目标的方案并说明取舍。意图仍无法确定且不同选择会改变结果时，在修改前使用提问工具确认。不得发明新行为；除非用户明确改为放弃本次操作，否则继续解决，不执行 `--abort`。

4. **运行项目检查。** 查明项目已有的自动化检查并执行与冲突范围相称的检查，通常依次包括类型检查、测试和格式检查。只修复本次冲突解决引入的问题。

5. **完成 merge/rebase。** 只暂存本次冲突解决涉及的文件，不吸收无关改动；继续当前操作。若 rebase 后续提交产生新冲突，重复以上流程，直到 Git 不再报告未解决文件且 merge/rebase 状态已经结束。
