# Impl

每个 commit 只表达一个可独立理解和回滚的变更。`-w` 只强制使用隔离 worktree，不改变实现范围、任务依赖、提交和安全规则。

## 1. 确定实现单元

开始前检查主工作区已有的已暂存、未暂存和未跟踪改动。已有改动视为用户所有，不得自动 stash、覆盖、暂存或提交；仅当其与本次范围重叠且无法可靠分离时暂停。

按 `docs/agents/domain.md` 定位并使用相关 `CONTEXT.md`，遵守全部项目 RULES；相关 `CONTEXT.md` 不存在则静默继续。

从输入中确定独立实现单元：

- **任务卡输入**：读取目标、现状、方案和验收条件；只有 `Status: ready-for-agent` 的任务可以实施，`completed` 任务不重复实现
- **对话输入**：提取目标、范围、已确定方案和验收方式；上下文足够时直接实现，不要求先生成任务卡

仅当当前实现涉及模块职责、接口表面积、依赖接缝、adapter、测试面或模块深浅时，读取 `codebase-design`：

- **任务卡输入**：只用其词汇和准则把已确定的模块形状映射到真实代码，不得重新选择或扩大方案；代码事实证明方案不可行时按下方停止条件处理。
- **对话输入**：当前范围已经授权实现且模块形状可由需求、代码和项目规则收口时，用它完成必要设计；存在影响显著的可行方案分歧时，先调用 `grill-with-docs`，用户确认前不得实现。

普通局部修改、既有接口内的行为补充或不改变接缝的机械变更不得加载 `codebase-design`。

任务卡存在 `Blocked by` 时，读取引用的任务卡；只有依赖全部完成才解锁。依赖不存在、状态异常或形成循环时停止对应任务并报告。一次输入多个任务时，只实施当前已解锁的任务，其余任务等待依赖集成。

多个可独立完成的改动分别形成实现单元。一次输入多张任务卡时，每张已解锁任务卡必须在彼此隔离的执行上下文中实施；可以使用独立 Agent、fork Agent、独立任务或宿主提供的等效机制，不要求从空白上下文启动。单张任务卡或对话输入继续使用当前上下文。存在依赖时，前置任务提交并集成后，后续任务基于最新目标分支，在与其他任务卡隔离的执行上下文中实施。

上下文隔离不决定 worktree、执行者或串并行策略。并行任务必须使用独立 worktree、Git 索引和临时分支，否则串行实施。

只有缺失信息真正阻塞实现时，才调用 `grill-with-docs` 与用户对齐。

## 2. 选择执行方式

用户明确指定 worktree 或当前工作区时直接遵循。未指定时自动选择：

- **当前工作区**：范围集中，已有改动不重叠，或 worktree 的创建与集成开销大于隔离收益
- **隔离 worktree**：需要保护已有改动，范围较广或风险较高，或多个实现单元需要隔离

开始实现前简要说明选定方式和一项关键依据，不请求确认。仅当改动归属、实现范围或隔离收益无法从任务卡和代码事实中判断，且两种方式利弊接近时，才使用提问工具。确定后除非用户重新指示，不自动切换或降级。

隔离模式下，每个独立交付的实现单元使用独立 worktree 和临时分支；依赖任务集成后，后续任务才从最新目标分支创建 worktree。共享写集或明显冲突的任务串行处理。无法安全创建 worktree 时暂停并说明原因。

## 3. 实现、验证与提交

逐个实现单元执行：

1. 查看现有代码和相关 Skill，将已确定方案映射到实际结构，只做范围内的最小修改；优先复用现有能力，不确定的框架 API 先查本地用法再查 references。
2. 不重新选择已收口的主要方案。代码事实证明方案不可行或矛盾时停止并报告；发现需要扩展范围、改变方案或增加任务依赖时重新拆分。
3. 完成与范围相称的测试和验收，只暂存当前实现单元的改动并检查 staged diff，确认实现、验证和 diff 符合任务目标及项目规则。
4. 全部通过后交付原子 commit。一个任务默认一个 commit；确有多个可独立理解和回滚的变更时，按顺序交付多个 commit。

默认不调用 `code-review`。用户明确要求代码评审时，将它作为独立流程调用，不把它作为本 Skill 的默认完成门槛。

当前工作区模式按依赖顺序串行完成上述循环。隔离模式下，每个 worktree 只处理对应实现单元，不修改任务卡状态，并记录全部 SHA 及其目的；不得交付 WIP、fixup 等过程性提交。

## 4. 集成与状态流转

当前工作区模式提交后直接更新任务状态。隔离模式按任务卡编号或实现单元顺序，完整 cherry-pick 每个实现单元的全部 commits：

- 冲突时中止本次集成并保留 worktree；在对应 worktree 中基于最新目标分支处理。冲突来自主工作区相关未提交改动时暂停
- 单个任务失败不影响无依赖任务，只阻塞依赖它的后续任务
- 集成成功后移除 worktree 和临时分支；失败时保留并报告路径、分支和原因

实现单元成功提交或集成后，将对应任务改为 `completed`；同一 `tasks/` 目录下全部任务均为 `completed` 时，统一改为 `archived`。任务卡或 PRD 是否进入实现 commit 由本次范围决定。
