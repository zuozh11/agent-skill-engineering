# To API

将锁定 PRD 写成一份接口规划契约，存放在该 PRD 同目录的 `API清单.md`。

成稿前完整读取 [验收样例](references/accepted-example.md)，校准章节形状、信息密度和表达方式。样例不提供本次业务事实。对象图深度、接口数量、内部入口和停用入口以本次 PRD 为准；没有的章节整节省略。

## 流程

### 1. 定位锁定 PRD

用户指定路径则使用该 `PRD.md`。否则使用当前对话已写入的 PRD。找不到锁定 PRD 时停止，提示先 `to-prd` 或指定已有 PRD，不成稿。

PRD Scope 中没有承担接口的后端交付单元时停止并说明。只规划当前仓库（或用户指定的交付单元）；其他系统只作为调用方或内部触发方出现。

**完成标准：** 已确定唯一的 `PRD.md` 路径和本次规划的交付单元。

### 2. 加载项目上下文

使用已加载的 CONTEXT 术语与 RULE。尚未加载则按项目知识协议执行；知识不可用时继续并如实说明。

**完成标准：** 正文术语与 CONTEXT 对齐。

### 3. 收口接口形状

读取 PRD 的 Scope、Requirements、Out of Scope 和 Implementation Decisions。对照交付单元内现有公开路由、生成式维护入口，以及会改变本资源状态的内部调用（发包、回调、任务），标成改造、新增、内部或停用：

- **改造 / 新增**：本期前端或其他外部调用方要打的业务路由
- **内部**：改变业务状态，但不对前端新增路由
- **停用**：现有公开路由本期下线

优先改造已有路由。新路由沿用该模块现有 Controller 前缀和 `POST /{module}/{method}` 风格。写入语义与现有 Save 不一致时，新增命令或内部入口，并将原公开 Save 列入停用。同一路由被多个入口调用时，用请求字段区分，不复制多条同类接口。

平台通用能力继续复用，不列入交付接口：登录鉴权、BPM 待办与提交/退回/驳回、公共附件上传下载、相邻主数据详情。

页面内切换、勾选、批量填写若仍使用详情已返回的对象图，不新增查询或保存接口；把「这些 ID 只在首次详情结果里流转」写在场景调用。

子资源留在聚合对象图里，不按表拆路由。这条写在资源与标识，文末不重复。

无法从 PRD 和代码确认、且会改变接口总表、对象图边界、复用还是新增、补丁还是整单覆盖、失败是否整批回滚的决策，调用 `grill-with-docs` 并等待用户确认。能查证的现状不转交用户。多条 ID 一批提交时，失败按整批回滚来写，除非用户确认允许部分成功。

**完成标准：** 每个拟写接口都有状态、调用方、主标识和对象图边界；每个前端场景都有接口顺序和跨接口 ID；未决的接口形状决策已关闭。

### 4. 拟稿并写入

使用下方模板，写入 PRD 同目录 `API清单.md`，覆盖已有同名文件。无需询问是否发布。

公开接口按实际调用顺序编号，全部写在 `接口规划` 下。按种类选用小节，不凑齐标题：

- 查询：请求、响应、不做
- 命令：请求、成功副作用、失败、不做
- 请求只剩一个 ID、且前端显隐不能代替执行条件时，用「服务端必须重校验」写出可执行条件

列表响应按定位 / 展示 / 跳转归类。聚合响应用对象图。命令写同一业务操作内必须完成的副作用，以及成功是否返回业务对象。失败写整批还是单条、留下什么、返回业务文案。

场景调用使用「场景 / 接口顺序 / 跨接口数据」表。

正文只保留会改变路由集合、对象图、副作用、失败语义或跨接口 ID 的句子。标识表承担易混 ID 的定义。代码只用来查证，正文写路由、业务对象和状态变化。

写入后检查 Markdown 标题与表格完整；对已跟踪文件使用 `git diff --check`，新建文件使用 `git diff --no-index --check /dev/null <file>`。

**完成标准：** 文件已写入 PRD 同目录；接口总表覆盖全部拟交付的公开、内部和停用入口；每个公开接口出现在至少一个场景；每条跨接口 ID 能在标识表中找到「谁产生 / 后续谁用」；密度与验收样例同级。
