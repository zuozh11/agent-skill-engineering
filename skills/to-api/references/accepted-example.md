# 技术评标 API 清单

## 文档用途

本文是接口规划契约，只回答三件事：

1. 本次对外暴露哪些接口、停用哪些接口、哪些能力根本不进 Controller。
2. 每个接口的调用方、标识、对象图边界、副作用和失败语义。
3. 接口之间传递哪些 ID，以及一次用户动作会打到哪些接口。

本文不是 Swagger / OpenAPI，不枚举快照字段、分页外壳和平台通用参数。字段级契约留给实现后的 API 文档；页面显隐、二次确认和节点裁剪留给前端与联调说明。

需求来源：[技术评标 PRD](./PRD.md)。交付单元是生产寻源服务；Web 前端是调用方，不在本文展开页面逻辑。

## 资源与标识

技术评标是唯一对外资源。五层聚合是详情内部结构，不按表拆 Controller。

```text
技术评标                             bidId / businessKey
├── 评标供应商                       bidSupId
│   ├── 供应商 RFQ 类型汇总           bidSupRfqId
│   └── 供应商物料                   bidSupPartId
│       └── 物料 × RFQ 类型原子评审   bidSupPartRfqId
└── 整单评标附件                     关联 bidId，用附件类型区分技术/质量
```

| 标识 | 含义 | 谁产生 | 后续谁用 |
| --- | --- | --- | --- |
| `bidId` | 技术评标主键 | 发包初始化 | 列表、审核、开标、详情、评审保存 |
| `businessKey` | 技术评标流程业务键，与 `schemeBusinessKey` 不得同名混义 | 发包初始化 | BPM 待办进入详情 |
| `pkgId` | 咨询包 ID | 咨询包既有数据 | 列表跳转咨询包；开标内部定位应标集合 |
| `schemeBusinessKey` | 咨询方案跳转键 | 咨询包/方案既有数据 | 仅列表跳转咨询方案，不参与评标流程 |
| `bidSupId` | 评标供应商 | 发包初始化 | 详情内切换供应商；不作为独立查询参数 |
| `bidSupPartId` | 评标供应商物料 | 发包初始化 | 详情物料行定位 |
| `bidSupPartRfqId` | 原子评审主键 | 发包初始化 | 评审保存、明细附件关联 |
| `rfqType` | 技术 / 质量 | 发包初始化 | 当前分支保存和附件隔离 |

## 接口总表

| 状态 | 接口 | 调用方 | 用途 |
| --- | --- | --- | --- |
| 改造 | `POST /pd/pdBidQueryPage` | 开标审核、采购员开标、技术评标查询 | 咨询包一行的技术评标分页列表 |
| 改造 | `POST /pd/pdBidDetail` | 流程详情、评标报告、跳转查看 | 一次返回完整五层聚合和全部附件 |
| 新增 | `POST /pd/pdBidOpenAudit` | 开标审核列表 | 批量通过或不通过 |
| 新增 | `POST /pd/pdBidTechOpen` | 采购员开标列表 | 技术开标并启动并行评审 |
| 新增 | `POST /pd/pdBidReviewSave` | 技术/质量工程师流程提交前 | 保存当前 RFQ 类型的结论、说明和附件 |
| 内部 | 咨询包发包初始化技术评标 | 咨询包发包事务 | 生成待开标审核快照 |
| 内部 | BPM 最终通过回调 | 通用流程能力 | 汇总、完成技术评标、生成商务评标 |
| 停用 | `POST /pd/pdBidSave` | 原生成式维护 | 公开入口下线；发包改为内部初始化 |
| 停用 | `POST /pd/pdBidDelete` | 原生成式删除 | 本期无删除评标 |
| 停用 | `POST /pd/pdBidExport` | 原生成式导出 | 本期无导出 |
| 停用 | `POST /pd/pdBidImport` | 原生成式导入 | 本期无导入 |

平台通用能力继续复用，不写入本清单的交付接口：登录鉴权、BPM 待办列表、BPM 提交/退回/驳回、公共附件上传下载、咨询方案详情、咨询包详情。

## 场景调用

| 场景 | 接口顺序 | 跨接口数据 |
| --- | --- | --- |
| 采购室主任批量审核 | 列表 `scene=OPEN_AUDIT` → 开标审核 | 列表行 `bidId[]` + 统一结论和意见 |
| 采购员技术开标 | 列表 `scene=TECH_OPEN` → 开标 | 列表行 `bidId` |
| 工程师办理评审 | BPM 待办带 `businessKey` → 详情 → 当前分支保存 → 平台审批 | 详情中的 `bidId`、`bidSupPartRfqId`、本类型附件 |
| 室主任或部长审批 | BPM 待办 → 详情 → 平台审批 | 只读详情，不再调评审保存 |
| 查询与报告 | 列表 `scene=QUERY` → 详情 | 列表行 `bidId`；完成状态才进入报告展示 |

前端切换供应商、勾选物料、批量填结论都不发新的查询请求。这些 ID 只在首次详情结果里流转。

## 接口规划

### 1. 共用技术评标列表

**`POST /pd/pdBidQueryPage`**

三个菜单调用同一分页接口。列表粒度永远是一个咨询包一行，不按物料展开。

#### 请求

| 字段 | 规则 |
| --- | --- |
| `scene` | 必填。`OPEN_AUDIT` 固定待开标审核；`TECH_OPEN` 固定待技术开标；`QUERY` 全部技术评标，可再叠加 `bidStatus` |
| `pkgCode` | 咨询包编号，模糊，未传不筛 |
| `bidStatus` | 评标状态精确匹配；`OPEN_AUDIT` / `TECH_OPEN` 忽略调用方传入的状态 |
| `partCode` / `partName` | 关联物料模糊筛选，命中后仍返回咨询包行 |

固定范围：当前租户、当前采购组织、有效技术评标；非超管按授权采购员过滤。

#### 响应

列表投影，不返回供应商明细和附件。

- 定位：`bidId`、`pkgId`、`schemeBusinessKey`、`businessKey`
- 展示：咨询方案编码，咨询包编码、标题，技术评标状态，开标审核结论和意见，技术应标已提交数、应邀数，技术/商务应标截止时间，发包时间，采购工程师
- 跳转：`schemeBusinessKey` 打开咨询方案；`pkgId` 打开咨询包
- 报告入口：用完成状态判断，不另返开关字段
- 应答进度：返回两个整数，前端拼 `已提交数/应邀数`；口径复用咨询包列表，不在评标主表持久化

#### 不做

- 不返回 BPM 待办。
- 不在列表接口里执行审核或开标。

### 2. 技术评标完整详情

**`POST /pd/pdBidDetail`**

流程页、查询查看、完成状态报告共用。后端返回全量，不按节点、角色或供应商裁剪。

#### 请求

`id`、`businessKey` 任一非空。两者都空时返回业务文案。数据范围与列表相同。

#### 响应

```text
技术评标
├── 主表业务字段、流程展示字段、开标审核事实、开标事实
├── 整单评标附件                          含技术/质量类型
└── 评标供应商[]
    ├── 供应商快照、技术响应、总评
    ├── 供应商 RFQ 类型汇总[]             技术、质量
    └── 供应商物料[]
        └── 原子评审[]                    该物料技术、质量
            ├── 结论、说明、结论来源、评标人、评标时间
            ├── RFQ 原件
            ├── 供应商回复
            └── 工程师明细附件
```

结论来源必须返回，供前端识别系统自动 `NG` 后结论只读。完成状态与评标中返回同一对象图。报告矩阵由前端组装，后端不生成报告 JSON。

未完成的技术评标仍可按 `bidId` 或 `businessKey` 查询详情，供流程办理使用；不因“查看报告”额外拦截。

#### 不做

- 不拆技术详情、质量详情、报告详情。
- 不按当前供应商二次查询。
- 不在详情接口保存数据或推动流程。

### 3. 批量开标审核

**`POST /pd/pdBidOpenAudit`**

采购室主任在列表多选后提交。不发起 BPM。

#### 请求

```text
bidIds[]              一个或多个技术评标 ID
bidOpenConc           通过 / 不通过
bidOpenOpinion        选填，整批共用
```

#### 成功副作用

整批每条写入审核结论、意见、审核人和审核时间，状态改为待技术开标。通过、不通过走同一状态迁移。是否可开标只看结论。成功不返回业务对象。

#### 失败

任一记录不是技术评标、不是待开标审核、不在数据权限内，或整批为空：整批失败，不产生部分审核结果。返回面向办理人的业务文案。

#### 不做

- 不校验技术应标截止时间和提交进度。
- 不在本接口开标、改应标、写原子结论或发起流程。
- 不提供单条审核专用接口。

### 4. 技术开标

**`POST /pd/pdBidTechOpen`**

请求只传 `bidId`。前端列表显隐不是最终依据。

#### 服务端必须重校验

技术评标、待技术开标、尚未开标、审核结论通过、当前登录人属于该评标采购员范围，且已到技术应标截止时间或技术应标已全部提交。分子分母口径与列表、咨询包列表相同。

#### 成功副作用，同一业务操作内完成

1. 当前咨询包全部有效供应商应标写为技术已开标。
2. 技术未提交且仍待技术/待商务应标的改为逾期未应标；不伪造已提交、提交时间和商务响应。
3. 冻结供应商技术响应、说明以及 RFQ 原件和回复附件关联。
4. 未响应、技术放弃、逾期供应商的全部技术/质量原子结论写为 `NG`，记录结论来源和服务端时间，不伪造工程师。
5. 主表记录已开标、开标人和开标时间，状态改为技术评标中。
6. 发起技术评标流程，变量至少包含技术工程师 ID、质量工程师 ID，直接进入两个并行工程师节点。

不执行报价或附件解密。不另建流程任务资源。应标开标与逾期处理在本命令内部完成，不另开接口。

#### 失败

条件不满足时返回业务文案，例如审核未通过、未到截止且未全部提交、已经开标、当前人不是该评标采购员。

### 5. 当前分支评审保存

**`POST /pd/pdBidReviewSave`**

技术和质量工程师在流程提交前调用。室主任、部长不调用。页面没有独立暂存，这是唯一业务写入接口；批量改结论、批量传附件都在前端合并进这次请求。

#### 请求

```text
bidId
rfqType                               本次分支：技术 或 质量
整单附件                              本类型整单附件的完整集合
原子行[]                              本类型全部原子行，不是勾选子集
├── bidSupPartRfqId
├── 结论                              OK / NG
├── 结论说明                          人工 NG 时前端必填
└── 明细附件                          该原子行明细附件完整集合
```

保存语义是当前分支补丁，不是整单覆盖：

- 只更新请求 `rfqType` 的原子行和该类型附件。
- 未出现在请求里的另一类型结论和附件必须保持不变。
- 系统自动 `NG` 的结论和说明不得被请求改写；其明细附件仍可增删。
- 评标人和评标时间由服务端写入人工维护的行。
- 本接口不计算类型汇总和供应商总评；汇总结论只在流程最终通过时全量重算。
- 本接口不提交 BPM、不改评标业务状态。

页面必填由前端负责。后端校验身份、数据范围、记录归属和自动 `NG` 不可改结论。RFQ 原件和供应商回复不是本接口的可写集合。明细附件关联 `bidSupPartRfqId`，整单附件关联 `bidId` 并用附件类型区分。

成功不返回完整聚合。前端再调平台通用审批；需要回显时重查详情。

#### 失败

记录不属于当前技术评标、`rfqType` 与原子行不一致、试图改写自动 `NG` 结论、当前数据不在权限范围：整单失败。不删除另一分支已有附件。

## 内部入口

这些能力改变业务状态，但不对前端新增路由。

### 发包初始化

咨询包需要 RFQ 时，发包事务内部生成一条技术评标：状态待开标审核；快照采购员、技术/质量工程师、供应商和物料；每个供应商物料生成技术和质量两条原子行，结论为空；每个供应商生成技术和质量两条类型汇总，结论为空。不需要 RFQ 时仍按既有规则直接生成商务评标。不走公开保存接口，不发起流程。

### 流程最终通过

只有 BPM 回调为最终 `PASS` 时：全量计算并持久化类型汇总和供应商总评；技术评标置为完成；创建一条待开标审核商务评标，复制全部供应商、全部物料、三层结论和来源技术记录 ID，不复制任何附件。取消或最终拒绝只同步 BPM 状态。重复 `PASS` 不得重复创建商务评标。

退回、驳回、再次提交由 BPM 模板控制，业务服务只同步 BPM 状态，不提供“退回评标”接口。

## 停用公开入口

| 现有路由 | 原因 |
| --- | --- |
| `POST /pd/pdBidSave` | 整单保存会覆盖另一分支，且会误启动流程；发包改为内部初始化 |
| `POST /pd/pdBidDelete` | 本期无删除 |
| `POST /pd/pdBidExport` | 本期无导出 |
| `POST /pd/pdBidImport` | 本期无导入 |
