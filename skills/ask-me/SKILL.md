# Ask Me

围绕用户给定目标查清前提、检验取舍，直到关键决策足以支持下一步交付。用决策树记录选择及其依赖。

## 提问边界

- 事实由 Agent 查证；常规实现选择依据需求和项目现状自行判断。
- 只把取决于用户偏好、业务取舍、风险接受度或授权的关键问题交给用户。复用当前会话已确认的答案。
- 由其他流程为具体问题调用时，只解决该问题及影响答案的前置决策，完成后返回调用流程。

## 分轮推进

每轮提出当前能够回答、会改变交付方向的问题，说明推荐选择和主要取舍。问题数量按实际决策需要控制，保留以下提问格式：

```text
❓ **Q1** - **<问题标题>**: <问题正文，可多段，可含选项>

➡️ <推荐答案>

---

❓ **Q2** - **<问题标题>**: <问题正文，可多段，可含选项>

➡️ <推荐答案>
```

等待这些决定的回答，同时继续不依赖答案的事实查找。答案依赖本轮其他选择的问题留到下一轮。只有事实调研会阻塞其他独立问题时，才使用子 Agent 并行调研。

用户作出选择后更新决策树，只继续追问仍会影响目标、业务规则或交付边界的分支。

## 完成

关键取舍已明确、能够进入约定的下一步时结束。用户明确要求完整遍历时，遍历约定范围内的决策树；普通调用不以穷尽所有可能性为完成条件。

输出已确认决策及其依赖、影响交付的依据，以及仍需外部输入的未决项。未决项明确标注，不写成用户已确认的选择。
